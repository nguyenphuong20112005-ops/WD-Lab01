PHẦN 3 — INTERVIEW QUESTIONS GIẢ ĐỊNH

Lý thuyết | Code Interview

Phần 1. Các câu hỏi phỏng vấn

Câu 1: Tag và element khác nhau như thế nào? Cho ví dụ.

  • Tag là thẻ đánh dấu cú pháp HTML, ví dụ <p>, </p>, <h1>.
  • Element là toàn bộ cấu trúc hoàn chỉnh gồm thẻ mở + nội dung + thẻ đóng.

Ví dụ: Trong file bai1.html:

<h1>Trường Đại học Khoa học Tự Nhiên - ĐHQG.TPHCM</h1>
  • <h1> và </h1> là hai tag.
  • Cả dòng là một element.

Câu 2: Vì sao HTML document nên có <!DOCTYPE html>?

<!DOCTYPE html> khai báo tài liệu là sử dụng HTML chuẩn hiển thị hiện đại thay vì chế độ tương thích cũ.

Câu 3: Vai trò của <head> và <body> khác nhau như thế nào?

  • <head> : Chứa thông tin cấu hình và metadata của trang bao gồm title, meta charset, meta viewport, link CSS.
  • <body> : Chứa nội dung hiển thị trên trang như heading, paragraph, image , table và form.

Câu 4: charset="UTF-8" khác với lang="en" ở điểm nào?

  • code>charset="UTF-8" : Xác định cách mã hóa ký tự — giúp hiển thị đúng văn bản.
  • lang="en" : Khai báo ngôn ngữ nội dung chính — hỗ trợ screen reader, SEO, trình dịch.

Câu 5: Vì sao cần meta viewport trong tài liệu HTML hiện đại?

meta viewport giúp trang sử dụng chiều rộng phù hợp với màn hình mobile, thay vì mặc định hiển thị viewpoint như trên desktop.

Câu 6: Phân biệt paired element và void element. Vì sao <img> không có closing tag?

  • Paired element thường có thẻ mở + nội dung + thẻ đóng. Ví dụ: <p>...</p>.
  • Void element chỉ có thẻ mở, không có nội dung và thẻ đóng. Ví dụ: <img>, <br>, <hr>, <meta>, <input>,...

<img> không có closing tag vì nó không chứa nội dung text như paragraph.

Câu 7: Attribute nằm ở đâu? Giải thích href, src, alt, id và class.

Attribute nằm trong thẻ mở, sau tên thẻ, dạng name="value" và cung cấp thông tin bổ sung cho element.

  • href: Xác định đích đến của liên kết.
  • src: Xác định nguồn tài nguyên ví dụ như đường dẫn hình ảnh.
  • alt: Text mô tả ảnh cho screen reader.
  • id: Định danh duy nhất cho 1 element.
  • class: Nhóm nhiều element cùng loại.

Câu 8: Parent, child, sibling, descendant là gì? Chỉ ra trong source của bạn.

  • Parent : Thẻ cha trực tiếp bao quanh.
  • Child : Thẻ con trực tiếp nằm trong parent.
  • Sibling : Các thẻ cùng cấp, cùng parent.
  • Descendant : Mọi thẻ nằm trong parent ở bất kỳ cấp nào.

Chỉ ra trong source: Trong index.html:

<section id="about">              <là parent của figure >
    <h2>About Me</h2>
    <figure>                       <là child của section >
        <img src="images/profile.jpg" alt="..." width="...">   <là descendant của section >
        <figcaption>...</figcaption>                <là sibling của img >
    </figure>
</section>
  • section là parent của figure.
  • img và figcaption là child của figure.
  • img và figcaption là sibling với nhau.
  • img là descendant của section.

Câu 9: Tại sao nesting phải đóng từ trong ra ngoài? Cho ví dụ crossing tags sai.

Các element phải được lồng đúng theo thứ tự để HTML có được cấu trúc hợp lệ. Element mở sau phải được đóng trước.

Ví dụ về crossing tags sai: 

<p>Learning <strong>HTML</p></strong>

→ <p> mở trước nhưng đóng trước <strong>.

Sửa lại cho đúng: 

<p>Learning <strong>HTML</strong></p>

<strong> mở sau, đóng trước.

Câu 10: Khi nào dùng <p>, <br> và <hr>?

  • <p>: Dùng để tạo một đoạn văn.
  • <br>: Dùng để xuống dòng trong cùng một nội dung khi việc ngắt dòng có ý nghĩa.
  • <hr>: Biểu thị sự chuyển chủ đề hoặc ngắt nội dung theo chủ đề, thường được trình duyệt hiển thị thành đường kẻ ngang.

Câu 11: Vì sao không nên nhảy heading từ h1 xuống h3 chỉ để chữ nhỏ hơn?

Heading thể hiện cấu trúc phân cấp của nội dung, không phải kích thước chữ.

Khi nhảy từ h1 xuống h3:

  • Sẽ phá vỡ logic phân cấp.
  • Khi đó screen reader đọc sai cấu trúc.
  • Để điều chỉnh kích thước chữ nên dùng CSS.

Câu 12: External link, relative link và fragment link khác nhau như thế nào?

  • External link : Đường dẫn liên kết đến website khác. Ví dụ: <a href="https://github.com">
  • Relative link : Đường dẫn tương đối đến file hoặc thư mục khác trong dự án. Ví dụ: <a href="bai1.html">
  • Fragment link : Liên kết đến chỗ có định danh trong trang, thường dùng #id . Ví dụ: <a href="#about">

Câu 13: alt của <img> khác figcaption ở điểm nào?

  • alt: alt là văn bản thay thế cho hình ảnh khi hình ảnh bị lỗi.
  • figcaption: Hiển thị chú thích bên dưới ảnh.

Câu 14: Semantic HTML là gì? Vì sao header/nav/main/section/article/footer tốt hơn chỉ dùng div?

Semantic HTML là dùng các element có ý nghĩa mô tả vai trò nội dung.

Lợi ích của việc sử dụng header/nav/main/section/article/footer thay vì chỉ dùng div:

  • Các element này sẽ giúp screen reader hiểu rõ cấu trúc hơn.
  • Code sẽ dễ đọc hơn, nhìn thẻ sẽ biết vai trò.

Câu 15: Giải thích hierarchy đúng của table: table → thead/tbody → tr → th/td.

Cấu trúc phân cấp:

table
├── thead
│   └── tr
│       ├── th
│       └── th
└── tbody
    └── tr
        ├── td
        └── td
  • table: Bao toàn bộ bảng.
  • thead: Tiêu đề cột.
  • tbody: Dữ liệu.
  • tr: Một hàng.
  • th: Ô tiêu đề.
  • td: Ô dữ liệu.

Câu 16: Quan hệ giữa <label for="email"> và <input id="email"> là gì?

for của <label> phải liên kết với id tương ứng của <input> để khi người dùng nhấn vào label, trình duyệt có thể chuyển focus đến trường nhập liệu.

Câu 17: Tại sao form trong Lab01 chưa thực sự gửi/lưu đơn hàng hoặc thông tin người dùng?

Form trong Lab01 là form tĩnh, chỉ định nghĩa giao diện nhập liệu và cách gửi dữ liệu. Để xử lý đơn hàng hoặc lưu thông tin, thường cần có endpoint bên chỗ server, backend để nhận và xử lý dữ liệu, cùng cơ chế lưu trữ phù hợp.

Câu 18: Vì sao browser vẫn có thể render HTML sai? Developer cần kiểm tra gì ngoài output?

Browser thường cố gắng sửa hoặc diễn giải với HTML lỗi, nó tự động sửa lỗi sai và cố render. Điều này khiến HTML lỗi vẫn hiển thị trông có vẻ đúng , nhưng cấu trúc DOM bên trong có thể sai khác dự định .

Developer cần kiểm tra:

  1. Cấu trúc và thứ tự đóng mở tag.
  2. Đường dẫn ảnh, liên kết và tài nguyên.
  3. Hiển thị trên các kích thước màn hình khác nhau và khả năng sử dụng bằng bàn phím.

Câu 19: XAMPP/Apache đóng vai trò gì trong Lab01? localhost là gì?

  • XAMPP là bộ cung cấp môi trường phát triển web cục bộ. Bộ này gồm Apache + MySQL + PHP + Perl. Trong Lab01 chỉ dùng Apache .
  • Apache là web server chạy local, có thể nhận HTTP request và phục vụ cho file HTML trong dự án.
  • localhost là tên máy chủ hay địa chỉ IP trở về chính thiết bị đang chạy.

Câu 20: git add, git commit, git pull và git push khác nhau như thế nào?

  • git add .: Đưa các thay đổi vào staging area để chuẩn bị commit.
  • git commit -m "msg": Lưu các thay đổi trong staging thành một phiên bản trong lịch sử Git ở máy local.
  • git pull: Lấy thay đổi từ remote (GitHub) và tích hợp vào nhánh local hiện tại.
  • git push: Đẩy các commit từ local lên remote repository.

Phần 2. Code Interview Mini-Questions

Code Interview A

Code lỗi:

<p>Learning <strong>HTML</p></strong>

Lỗi:

Nesting sai vì <strong> mở sau nhưng đóng trước <p>.

Sửa lại thành đúng:

<p>Learning <strong>HTML</strong></p>

Giải thích:

Nguyên tắc Last In, First Out: Thẻ mở sau phải đóng trước. <strong> là thẻ con của <p>, nên phải đóng <strong> trước khi đóng <p>.

Code Interview B

Code lỗi:

<img src="images/product.png">
<a href=#products>Products</a>

Lỗi:

  1. <img> thiếu alt nên vi phạm accessibility.
  2. href=#products thiếu dấu ngoặc kép nên không chuẩn HTML hiện đại.

Sửa lại thành đúng:

<img src="images/product.png" alt="Ảnh sản phẩm">
<a href="#products">Products</a>

Giải thích:

  • alt bắt buộc cho <img> để screen reader đọc và hiển thị khi ảnh lỗi.
  • Attribute values phải có quotes theo chuẩn HTML hiện đại.

Code Interview C

Code lỗi:

<label for="email">Email</label>
<input id="student-email" name="email" type="email">

Lỗi:

for="email" không khớp id="student-email" nên label không liên kết với input.

Sửa lại thành đúng:

<label for="student-email">Email</label>
<input id="student-email" name="email" type="email">

Giải thích:

for của <label> phải khớp chính xác với id của <input> để click label focus vào input và screen reader đọc đúng.

Code Interview D

Code lỗi:

<a href="#projects">Projects</a>

<section id="project">
    <h2>Projects</h2>
</section>

Lỗi:

href="#projects" (có s) không khớp id="project" (không s).

Sửa lại thành đúng:

<a href="#projects">Projects</a>

<section id="projects">
    <h2>Projects</h2>
</section>

Giải thích:

Fragment link #X phải khớp chính xác với id="X". Nếu sai ký tự → browser không tìm thấy → click không nhảy đi đâu cả.
